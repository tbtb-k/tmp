このツールについて：Microsoft 365 Copilot / Copilot Studio / Power Automate / Power Virtual Agents / Teams / SharePoint などから書き出したエージェント一覧CSVを読み込み、放置・不完全なエージェントを自動で洗い出し、所有者への通知から削除までを記録・管理するためのツールです。データはすべてブラウザ内だけで処理され、外部には一切送信されません。

削除対象の判断基準重要

このツールは「リマインド（通知）の基準」と「実際に削除してよい基準」を分けて管理します。まず自動判定で通知対象を洗い出し、所有者からの回答期限を過ぎて初めて「削除実行可」になります。

STEP 1 ── リマインド対象の自動判定：次の3つのルールのいずれか1つでも該当すると、リマインド対象としてフラグが付きます。基準日はツールを開いた日です。

ルール1：長期放置
Last Modified が本日から リマインド閾値（既定180日）以上前。半年以上どこも触られていない＝実質的に使われていない可能性が高いエージェントです。
判定式：経過日数 ≥ リマインド閾値
ルール2：Bot ID未設定
Bot Id が空欄。発行途中で放棄された、または正常に公開されていない不完全なエージェントです。運用管理台帳とも突合できません。
判定式：Bot Id が空文字 / 空白のみ
ルール3：放置テスト機
Name または Description に検証用キーワードを含み、かつテスト機閾値（既定90日）以上未更新。役目を終えたPoC・検証機が残っている状態です。
判定式：キーワード一致 AND 経過日数 ≥ テスト機閾値

STEP 2 ── 通知と回答期限を経て「削除実行可」へ

  1. ①通知待ち：リマインド対象で、まだ所有者に連絡していない状態。
  2. ②返信待ち（期限内）：1次通知を送った状態。回答期限は通知日＋猶予日数（既定14日）。
  3. ③最終通知が必要：1次通知の期限を過ぎても返信がない状態。最終通知を送ります（猶予は既定7日）。
  4. ④削除実行可：最終通知の期限も過ぎて無反応。ここで初めて削除してよい状態です。

加えて、強制削除閾値（既定365日）を超えたものは、通知の進み具合に関わらず「削除実行可」として扱います（例外は所有者からの継続申請が必要）。

ルール3で判定に使うキーワード（部分一致・大文字小文字を区別しません）

テスト ／ てすと ／ ﾃｽﾄ ／ test ／ PoC ／ poc ／ 検証 ／ 一時 ／ 試作 ／ トライアル ／ sample ／ サンプル ／ デモ ／ demo ／ 開発用 ／ 評価用 ／ 練習 ／ お試し ／ 破棄予定 ／ 廃止 ／ 不要 ／ dummy ／ ダミー ／ 仮運用 ／ 仮設置

閾値既定値意味
リマインド閾値180日ここに達したら所有者へ確認通知を出す（まだ消さない）
テスト機の未更新日数90日検証用キーワードを含むものはこの日数で通知対象にする
1次通知の猶予日数14日1次通知からこの日数を過ぎたら最終通知へ
最終通知の猶予日数7日最終通知からこの日数を過ぎたら削除実行可
強制削除閾値365日通知の進行に関わらず原則削除とみなす日数

閾値はすべて画面右上の 設定ボタンから変更でき、ブラウザに保存されます。

注意：自動判定はあくまで機械的な「候補出し」です。基幹業務で年1回だけ動くエージェントなど、長期未更新でも現役のものはあります。削除の前に必ず所有者へ通知し、回答期限を設けてください。それがこのツールの通知フローです。

推奨する運用サイクル

「毎月の通知」と「四半期の棚卸」を組み合わせる運用をおすすめします。担当者1名でも回せる分量です。

タイミングやることツール上の操作
毎月 第1営業日最新のエージェント一覧CSVを各管理センターから書き出し、ツールに投入。①通知待ちを確認CSVインポート →「①通知待ち」タブ
毎月 第2営業日所有者へ1次通知メールを送信。送信したものを記録「通知メール作成」→ 文面をコピーして送信 → 一括処理で「1次通知済み」に
通知から14日後返信がないものへ最終通知（「あと7日で削除します」）「③最終通知が必要」タブ → 一括処理で「最終通知済み」に
最終通知から7日後無反応のものを削除決定にし、実際の削除作業へ「④削除実行可」タブ → 一括処理で「削除決定」に → CSV出力
四半期ごと継続と回答されたものも含め全体を棚卸。所有者不在（退職者）の棚卸を実施「保有数ランキング」で所有者を確認

削除前に必ず入れたい「アーカイブ期間」

  • いきなり削除せず、まず無効化（停止）して30日間だけ残す運用を強く推奨します。「消したら実は使っていた」という事故のほぼすべてを、この30日が防ぎます。
  • Power Platform 系（Copilot Studio / Power Automate / Power Virtual Agents）は、削除前にソリューションとしてエクスポートしておけば復元できます。
  • 削除実施後は、このツールから出力したCSVを削除エビデンスとして保管してください。「いつ・誰に・いつまでに、と通知したか」が1ファイルに残ります。

例外（消してはいけないもの）の扱い

  • 年1回しか動かない決算処理系などは、所有者から回答をもらったうえで「対象外（例外登録）」にします。次回以降、通知フローから外れます。
  • 例外登録には必ず管理者メモに理由と次回見直し時期を書いてください。例外が増えすぎると棚卸の意味がなくなります。
  • 所有者が退職・異動している場合は、所属部門の長にエスカレーションします。「保有数ランキング」を作成者で表示すると、引き継ぎ漏れが見つけやすくなります。

通知メールを書くときの4つのコツ

  1. 所有者ごとに1通にまとめる。エージェント1件につき1通送ると必ず読まれなくなります。ツールの「通知メール作成」は所有者単位でまとめた文面を生成します。
  2. 「返信がなければ削除する」と明記する。これがないと誰も返信しません。期限は日付で書きます。
  3. 残す場合のアクションを1つだけ書く。「このメールに『継続』とだけ返信」程度の軽さにします。
  4. 対象を特定できる情報を入れる。エージェント名・最終更新日・環境ID。所有者本人でも「どれのこと？」となりがちです。

作業の保存と復元v1.4

読み込んだCSVごと、作業状態が自動で保存されます。ファイルを閉じて翌日また開いても、前回の続きから再開できます。オフラインのHTMLのままで、データが外に出ることはありません。

  • 自動保存：操作するたびに約1.5秒後、ブラウザ内のデータベース（IndexedDB）に保存されます。右上に「保存済 14:22」と表示されます。
  • 手動保存： ボタン、または Ctrl+S。すぐ保存して時刻を更新します。
  • 復元：次に開いたとき、読み込んでいたCSV・棚卸ステータス・通知履歴・閾値設定・比較の基準がすべて戻ります。
  • サンプルに戻したいとき：上部の枠にある「サンプルデータで試す」を押してください。

別のPCへ移す・引き継ぐときは「セッションファイル」を使います。上部の枠の「セッションを書き出す」で .json を保存し、移動先で「セッションファイルを読み込む」だけです。バックアップとしても使えます（担当者が代わるときの引き継ぎに便利です）。

自動保存はこのブラウザの、このPCの中だけです。ブラウザのデータを消すと消えます。 大事な区切りではセッションファイルの書き出しか、CSV出力をしておいてください。

元に戻す（Undo）v1.4

一括処理は数千件を一度に書き換えるため、直前の操作を取り消せるようにしています。

  • 右上の ボタン、または Ctrl+Z。
  • ボタンにカーソルを合わせると「何を・何件・いつ」戻すのかが表示されます。
  • このセッション中は最大20回分さかのぼれます。ファイルを閉じても直前の1回分は残ります。
  • 一括処理・リセット・個別のステータス変更が対象です（メモの入力は対象外）。

それでも戻せないところまで進んでしまった場合は、書き出しておいたセッションファイルやCSVから復元してください。

前月比較（差分検出）v1.4

先月と今月のCSVを比べて、新しく作られたもの・なくなったもの・更新されたものを出します。掃除した先から増えていないかを見るための機能です。

使い方はどちらでも

  • 自動：新しいCSVを読み込むと、それまで開いていたデータが自動的に「比較の基準」になります。毎月読み込むだけで、次の月から差分が出ます。ファイル名が同じでも中身が変われば更新されます。
  • 手動：「前月比較」ボタン →「ファイルを選択」で先月のCSVを指定（画面へのドラッグ＆ドロップも可）。

差分が出ると、絞り込みバーの上に 「前月比 ○○.csv：新規 300 / 更新 382 / なくなった 200」 と表示され、一覧の行にも 新規 更新 のバッジが付きます。プルダウン「前月比：すべて」で絞り込めます。

「新規」が「なくなった」を上回っていたら要注意です。掃除より増殖のほうが速いということなので、エージェントの作成権限や申請フローの見直しを検討してください。差分はCSVでも出力できます。

突合は AgentKey（Bot Id ベース）で行います。Bot Id が未設定のものは「名前＋環境ID」で照合するため、名前を変えると「なくなった＋新規」として現れます。

SharePointリストの作り方（回答を受ける台帳）連携

5,000件規模ではメールの返信を人が読むのは不可能です。所有者にSharePointリスト上で自分でステータスを更新してもらうのが唯一現実的な方法です。次の列でリストを1つ作ってください。

列名（内部名）型編集するのは誰か用途
Title1行テキストシステムエージェント名
AgentKey1行テキスト（索引あり）システム一意キー。更新時の突合に使う（Bot Id ベース）
BotId / Platform / EnvironmentId1行テキストシステム識別情報
OwnerEmail1行テキスト（索引あり）システム通知先・本人フィルタ用
PublisherName1行テキストシステム作成者
CreatedOn / LastModifiedOn日付システム棚卸の根拠
DaysIdle数値システム経過日数
DetectionFlags複数行テキストシステム自動判定の理由
NotifyStatus選択肢（索引あり）フロー未通知／1次通知済み／最終通知済み／回答済み／対象外
NotifiedOn / DueDate日付（DueDateは索引あり）フロー通知日と回答期限
OwnerResponse選択肢（索引あり）所有者本人未回答／継続する／削除してよい／判断中　★ここが心臓部
OwnerComment複数行テキスト所有者本人継続理由・用途
RespondedOn日付フロー回答日（変更トリガーで自動記録）
AuditStatus選択肢管理者未確認／継続／削除決定／保留
AdminMemo / LastCheckedOn複数行テキスト／日付管理者管理者の記録

権限設計：リスト全体は「表示のみ」、OwnerResponse と OwnerComment だけを所有者が編集できるようにします。列レベルの権限はSPOにないので、「ユーザー独自のアイテムの編集」＋フォームのカスタマイズ（Power Apps）で他列を読み取り専用にするか、割り切って全員編集可にして版管理（バージョン履歴）で担保するのが現実的です。

ビューは必ず3つ作ってください。「自分の担当分（OwnerEmail = [自分]）」「未回答（OwnerResponse = 未回答）」「削除実行可（AuditStatus = 削除決定）」。フィルタなしの全件ビューは5,000件のしきい値に引っかかって開けなくなります。

初期投入：このツールの「出力 / 連携」→SharePointリスト取込用CSVを使います。列の内部名がそのままヘッダーになっているので、リストの「Excel にエクスポート」の逆手順、または下のフロー①で流し込めます。

Power Automate で一斉通知する連携

このツールはメールを送りません（オフライン動作を守るため）。代わりに、Power Automate がそのまま読めるExcelテーブルを出力します。フローは4本作れば回ります。

用意するファイル（「出力 / 連携」ボタンから）

  • AgentAudit.xlsx（テーブル名 AgentAudit）… 台帳の元データ。SharePoint または OneDrive に置く
  • NotifyQueue.xlsx（テーブル名 NotifyQueue）… 所有者ごとに1行。宛先・件名・本文・担当分リンク・SendStatus 列つき
1
フロー① 台帳の投入・更新（月次 / 手動）
トリガー：手動 または スケジュール（毎月1日 7:00）
① Excel「表内に存在する行を一覧表示」← AgentAudit（ページネーションをON／しきい値 100000）
② SharePoint「複数の項目の取得」← 台帳リスト（ページネーションON）
③ Apply to each（並列度 20〜30）：AgentKey が一致する項目があれば「項目の更新」、なければ「項目の作成」
重要：OwnerResponse と OwnerComment は更新対象に含めないこと。所有者の回答を毎月上書きしてしまいます。
2
フロー② 一斉通知（月次）
トリガー：スケジュール（毎月2日 20:00・夜間推奨）
① Excel「表内に存在する行を一覧表示」← NotifyQueue、フィルター SendStatus eq '未送信'
② Apply to each（並列度 1〜5）：
　・Outlook「メールの送信 (V2)」宛先 OwnerEmail／件名 MailSubject／本文 replace(item()?['MailBody'], decodeUriComponent('%0A'), '<br>')
　・Excel「行の更新」SendStatus='送信済み'／SentOn=utcNow()
　・「遅延」1秒（スロットリング回避）
③ 送信完了後、SharePoint 側を NotifyStatus='1次通知済み'／NotifiedOn=utcNow()／DueDate=addDays(utcNow(),14) に更新
3
フロー③ 期限監視と最終通知（毎日）
トリガー：スケジュール（毎日 8:00）
① 3日前リマインド：NotifyStatus eq '1次通知済み' and OwnerResponse eq '未回答' and DueDate eq [3日後] → やんわり督促メール
② 期限切れ→最終通知：NotifyStatus eq '1次通知済み' and OwnerResponse eq '未回答' and DueDate lt [今日]
　→ 最終通知メールを送り、NotifyStatus='最終通知済み'／DueDate=addDays(utcNow(),7) に更新
③ 上長へのエスカレーション：2回無反応なら Office 365 ユーザー「マネージャーの取得」で上長を CC に追加
4
フロー④ 回答の反映と削除対象の確定（毎日）
トリガー：スケジュール（毎日 9:00）＋ 任意で 項目が作成または変更されたとき
① OwnerResponse eq '継続する' → AuditStatus='継続'／NotifyStatus='回答済み'／RespondedOn=utcNow()
② OwnerResponse eq '削除してよい' → AuditStatus='削除決定'
③ NotifyStatus eq '最終通知済み' and OwnerResponse eq '未回答' and DueDate lt [今日] → AuditStatus='削除決定'（無応答による削除）
④ 管理者へ日次サマリを1通だけ送る（件数と「削除実行可」ビューへのリンク）。1件ごとに通知するとすぐ読まれなくなります。

回答は集計するだけ。読む必要はありません。「未回答」ビューの件数を週次で見て、減っていれば順調。個別のメール返信を待つ運用をやめるのが、5,000件を回すための最大のコツです。

翌月の起点：SharePointリストを「Excel にエクスポート」して、そのCSVをこのツールに読み込んでください。通知ステータス・回答期限・所有者回答・管理者メモまで自動で復元されるので、前月の続きから棚卸を再開できます（AgentKey で突合しています）。

5,000件規模でハマるポイント必読

制限実際に起きること対策
SharePoint リストビューのしきい値 5,000件全件ビューが開けない／フローが失敗するOwnerEmail NotifyStatus DueDate OwnerResponse にインデックスを作成。ビューは必ずフィルタ付きにし、表示は100件単位
「複数の項目の取得」既定100件先頭100件しか処理されない（気づきにくい）設定でページネーションをON、しきい値を 5000〜100000 に
Outlookコネクタのスロットリング大量送信で 429 エラー、途中で止まる並列度1〜5＋遅延1秒。3,000通で約50分。夜間バッチにする
Exchange Online の送信上限1日10,000宛先／30通/分を超えると送信拒否宛先を分割して数日に分ける、または送信専用の共有メールボックスを使う
Excelコネクタの同時実行「行の更新」が競合して失敗するApply to each の並列度を1に。更新先をSharePointリストに寄せるのも手
そもそも宛先が多すぎる3,000人に送ると問い合わせ対応で業務が止まる初回は上位所有者から段階的に。保有数ランキングで見ると、少数の所有者が大量に持っているケースが多く、上位数百人で全体の大半をカバーできます

初回だけは絶対に段階展開してください。いきなり全件通知すると問い合わせが殺到します。まず「強制削除閾値超過」タブで絞った最優先分だけ、あるいは1部門だけで1サイクル回して、文面と手順を固めてから全体展開するのが安全です。

メールよりTeamsの方が回答率は上がります。Power Automate の「チャットまたはチャネルでアダプティブカードを投稿する」を使うと、カード上のボタンから直接回答してもらえます。ただし本文の作り込みが必要なので、まずはメール＋SharePointリンクで始めて、回答率が悪ければ移行するのがおすすめです。

数千件を一括で処理する

5,000件規模でも、絞り込み → 一括処理の2ステップで進められます。1件ずつクリックする必要はありません。

  1. 絞り込む：タブ（例：「④削除実行可」）＋検索＋プルダウンで対象を絞ります。
  2. 一括処理バーで実行：「絞り込み中の N 件を一括処理」から操作を選び「実行」。表示中のページだけでなく、条件に一致する全件が対象です。50件を超える場合は確認ダイアログが出ます。

例：「④削除実行可」タブを開いて、一括処理で「判断ステータスを『削除決定』に」を実行 → 該当する全件が一度に削除決定になります。

個別に選びたいときは、行のチェックボックスで選択してから下の一括変更バーを使います。ヘッダーのチェックボックスは今のページを選択し、その後に出る帯から条件に一致する全件へ広げられます。

表は1ページ100件ずつ表示されます（右下で50〜全件に変更可）。件数が多いときは「全件」にせずページ送りのほうが快適です。

通知メールの作り方

大前提：返信を待つ運用は5,000件では破綻します。このツールが生成する文面は、「返信不要。SharePointリストの自分の行を更新してください」という形になっています。

  1. まず設定（⚙）で SharePointリストのURL を登録します。これで本文に「あなたの担当分だけを表示するリンク」が自動で入ります（?FilterField1=OwnerEmail&FilterValue1=… 形式）。
  2. 「①通知待ち」タブなどで対象を絞り込みます。
  3. 上部の 「通知メール作成」 を押すと、所有者ごとにまとめた文面が生成されます。1人が10件持っていれば、10通ではなく1通です。
  4. 少人数なら「本文をコピー」で1通ずつ。大量なら「通知キューを出力 (.xlsx)」で、宛先・件名・本文が1行にまとまった Excelテーブル NotifyQueue を出力し、Power Automate に流します。
  5. 送信後、一括処理で「本日付で『1次通知済み』にする」を実行。回答期限が自動計算されます。

「③最終通知が必要」だけを絞り込んでから開くと、文面が自動で最終通知バージョン（「本メールが最終のご案内です」）に切り替わり、期限も最終猶予日数で計算されます。

※ このツールはメールを送信しません。文面とキューの生成までを担当し、送信は Power Automate に任せます。

基本の使い方（5ステップ）

  1. CSVを読み込む：管理センターから書き出したCSVを画面上部の枠にドラッグ＆ドロップ、または「CSVインポート」から選択します。文字コードは UTF-8 / Shift-JIS を自動判別します。
  2. 全体像をつかむ：KPIカード・フロー進捗・円グラフで、総数・通知対象・削除実行可の件数を確認します。どれもクリックで絞り込めます。
  3. 絞り込む：判定タブ（リマインド対象／長期未更新／Bot ID未設定／テスト用放置機）と運用フロータブ（①〜④）を組み合わせます。
  4. 判断を記録する：「判断ステータス」を 継続 / 削除決定 / 保留 から選び、「管理者メモ」に理由や引き継ぎ事項を書きます。一括処理も使えます。
  5. CSVで出力する：「棚卸結果をCSV出力」で、元の10カラムに判断結果・通知履歴を追加したCSVをダウンロードします。

2つのステータスの使い分け

通知ステータスは「所有者とのやり取りがどこまで進んだか」、判断ステータスは「最終的にどうするか」を表します。両方を記録しておくと、削除の根拠が後から説明できます。

通知ステータス意味次にすること
未通知まだ所有者に連絡していない通知メールを送り「1次通知済み」に
1次通知済み1回目の連絡を送った。回答期限あり期限まで待つ
最終通知済み期限切れで2回目（最終）を送った期限を過ぎたら削除決定へ
返信あり（継続）所有者から「使っている」と回答判断ステータスを「継続」に
返信あり（削除可）所有者から「消してよい」と回答判断ステータスを「削除決定」に
対象外（例外登録）年次処理など、通知フローから除外メモに理由と次回見直し時期を記入
判断ステータス意味メモに書くとよいこと
未確認まだ誰も見ていない初期状態—
継続現役で使うので残す用途・現在の利用部署・次回見直し時期
削除決定削除してよいと合意済み削除理由・合意した相手・削除予定日
保留所有者確認中／判断待ち誰に何を確認中か・いつまでに回答予定か

判断ステータスを「未確認」以外にすると、その日の日付が「最終確認日」として自動で記録され、CSV出力に含まれます。

データの保存とプライバシー

  • 入力したステータス・メモ・通知履歴・閾値設定に加えて、読み込んだCSVそのものも自動保存されます（ブラウザ内の IndexedDB）。ファイルを閉じても次に開いたときに前回の続きから再開できます。
  • 紐付けは Bot Id（未設定の場合は「エージェント名＋環境Id」）をキーに行います。同じエージェントであれば、翌月に新しいCSVを取得しても通知履歴が引き継がれます。
  • ブラウザや端末が変わると引き継がれません。複数人で回す運用なら、毎回CSVを出力して共有フォルダに置き、次回はそのCSVを起点にしてください。
  • 読み込んだCSVも入力内容も外部サーバーへは一切送信されません。オフライン環境でもそのまま動作します。
  • 右上の ボタンで、保存済みのステータス・メモ・通知履歴をすべて消去できます（元に戻せません）。

便利な操作

  • 行のどこか（名前・フラグ欄）や右端の ボタンをクリックすると詳細モーダルが開きます。Descriptionの改行もそのまま読めます。
  • 表のヘッダー（エージェント名・最終更新など）をクリックで並び替え。もう一度で昇順／降順が切り替わります。
  • 右端の「判断ステータス」「管理者メモ」列は固定表示なので、横スクロールしても入力できます。
  • Ctrl + F で検索窓へ移動、Esc でモーダルを閉じます。
  • 「サンプル」ボタンで、いつでも動作確認用の200件に戻せます。

うまく動かないとき

症状原因と対処
読み込んでも0件になる1行目がヘッダー行になっているか確認してください。列の順番は入れ替わっていても、列名が一致していれば読み込めます。
日付が「不明」になるLast Modified が空、または年月日を含まない形式です。2026-08-12- 04:13:37Z や 2026/08/12 などは自動で解釈します。
文字化けするUTF-8 / Shift-JIS を自動判別しますが、それ以外の文字コードの場合はUTF-8で保存し直してください。
ステータスが保存されないブラウザのプライベートモードや、サイトデータをブロックする設定では保存できません。通常モードで開いてください。
件数が多くて重い右下の表示件数を「100件」以下にしてください。集計は全件で行われるため、数値は変わりません。
